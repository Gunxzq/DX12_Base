**传统方案（你现在的位置）**：
- 标准阴影贴图：简单、兼容性好，但对高多边形场景性能差
- 级联阴影贴图（CSM）：只适合定向光源

**当前方案（UE 5 的主流）**：
- **虚拟阴影贴图**：用虚拟化技术，16K×16K 虚拟分辨率，按需渲染"页（Page）"，有缓存的可以复用，不动的物体不需要每帧重新渲染
- **光线追踪阴影**：利用硬件 RT，能产生正确的区域阴影（柔和半影）
- **MegaLights**：最新的随机直接光照技术，恒定开销，可以支持"比以前多几个数量级"的动态阴影光源

从这些演进可以看出，大型引擎一直在追求**用更灵活的方式管理"昂贵的阴影计算"**——无论是虚拟化、光线追踪还是随机采样，核心都是让开销可控。

## 4. 对你设计的启示

结合这些资料，我建议你可以这样规划：

**短期目标（你现在做的事）**：
- 保持 `Light` 和 `ShadowConstants` 解耦的设计方向
- 添加 `ShadowMapIndex` 作为关联，通过着色器独立访问

**中期目标（如果以后要扩展）**：
- 为不同类型的光源考虑不同的阴影策略（定向光用 CSM，点光源用立方体贴图阴影）
- 引入"阴影贴图缓存"的概念——不动的物体不需要每帧重新渲染

**长期参考（了解即可）**：
- 虚拟阴影贴图或光线追踪的架构思路
- 留意像 MegaLights 这样的新技术，它的随机采样+降噪的思路可能会成为未来的主流

总的来说，你现在的解耦设计方向是对的。UE 的经验表明，只有把光源和阴影分开管理，才能灵活地适配不同场景，也才能方便地升级或替换阴影技术。
