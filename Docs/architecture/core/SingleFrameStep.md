## 一、目的与背景

### 1.1 要解决的问题

> **✅ 已解决（2026-08-26）**：L2c 移动闪烁/绘制错乱（低频偶发）的根因已定位并修复
> （见 `Docs/bugs/BugFix_L2c_InstanceCulling_ContentCorruption.md`），"拿错误帧"
> 这一原始目标已达成，本文档使命完成。以下内容保留为**设计储备**——单帧步进作为
> 通用调试工具（暂停/精确步进/无输入命令回放），未来排查其他低频偶发问题时可直接实施。

移动闪烁/绘制错乱（低频偶发）排查卡在**拿不到错误帧**：

- 错乱帧未在抽样（节流 60~120 帧 + 抽样桶未覆盖）——日志采样盲区；
- GPU 内读取（VS flatInstanceIndex / gAppend）无运行时证据——需错误帧捕获；
- 低频偶发、无法稳定触发——无法按需重现。

### 1.2 单帧步进的价值

- **暂停**：画面冻结在最后渲染帧——错误帧稳定可见，不再一闪而过；
- **步进一帧**：手动推进一帧（相机移动/场景变化），逐步逼近错误帧；
- **错误帧观察**：步进到错乱帧时暂停 → 转储帧状态（帧号/可见实例数/桶数）→ 定案根因。

## 二、设计定案

### 2.1 控制状态（Editor 成员，Editor.h）

| 成员 | 类型 | 语义 |
|:--|:--|:--|
| `m_framePaused` | `bool` | 暂停标志——true 时主循环跳过 `FrameDriver::Tick`（画面冻结在最后渲染帧） |
| `m_stepOneFrame` | `bool` | 步进标志——true 时强制执行一帧后自动回暂停（消费式步进） |
| `m_stepFrameCount` | `uint32_t` | 步进累计帧数（错误帧定位/转储参考） |

### 2.2 主循环集成（Editor::Run while 循环）

```
while (m_isRunning && !ShouldClose) {
    MainTimer->Tick();           // 时间推进
    BackgroundExecutor->Tick();  // 异步加载继续（暂停时不阻塞）
    if (m_framePaused && !m_stepOneFrame) {
        Window->ProcessMessages();  // 暂停帧：仍处理窗口消息（防无响应）
        // 跳过 FrameDriver::Tick → 画面冻结
    } else {
        FrameDriver->Tick();        // 完整一帧（消息+输入+渲染+逻辑+Present）
        if (m_stepOneFrame) {
            m_stepOneFrame = false; // 步进消费，自动回暂停
            ++m_stepFrameCount;
        }
    }
    // ... 帧末处理（EndFrame/缩略图等）不变
}
```

**要点**：
- 暂停时**仍处理窗口消息**（`Window->ProcessMessages`）——保证窗口不无响应、可接收"恢复/步进"输入；
- 暂停时 **BackgroundExecutor 继续**——异步加载任务不受阻（对齐项目规则 15：编辑器主循环驱动 BackgroundExecutor）；
- 步进消费式：`m_stepOneFrame` 触发一帧后自动清零回暂停——**每次步进精确一帧**。

### 2.3 控制入口（ImGui 调试 UI）

- **暂停/恢复按钮**：切换 `m_framePaused`；
- **步进一帧按钮**：置 `m_stepOneFrame = true`（下一主循环迭代执行一帧）；
- **状态显示**：当前步进累计帧数 `m_stepFrameCount` + 帧号（`FrameDriver::GetFrameStats().frameNumber`）；
- 位置：DebugUIManager 调试面板或 Viewport 工具栏（实施时定）。

### 2.4 错误帧观察（核心流程）

1. **暂停**：移动相机到可疑区间后暂停——画面冻结；
2. **步进**：逐步进一帧（每次相机/场景变化一帧），观察画面；
3. **错误帧捕获**：步进到错乱帧 → 暂停 → 转储帧状态日志（帧号、可见实例数 readback、桶数、coarse 命中块数）；
4. **根因定位**：错误帧数据对照 `BugFix_L2c_InstanceCulling_ContentCorruption.md` 剩余疑点 A/B/C 验证。

### 2.5 无输入步进（关键：相机命令记录/回放，2026-08-11 补充）

> **核心问题（用户指出）**：错乱**只在相机移动时触发**——暂停后无实时输入，普通步进一帧
> 无法触发相机移动 → 步进失效（画面不动 = 不触发错乱）。需要**在无输入的情况下也能让相机
> 继续移动**，才能步进逼近错误帧。
>
> **解决方案（双端同步/命令序列模式）**：复用 `SnapshotSystem.md` L3 的**命令序列 + 按帧重演**
> （OperationRecorder 命令序列 → "游戏进程回放：按帧重演操作序列"，docs 已记载）——
> 记录相机输入命令，暂停步进时按帧重演，模拟相机移动触发错乱。

```
正常运行时：CameraCommandRecorder 每帧记录相机输入命令
  m_cameraCommands[帧号] = { 移动向量, 旋转增量 }   // 环形缓冲（如 1024 帧）
        │
暂停 + 步进时：无实时输入 → 从命令缓冲取下一帧命令【重演】
  Step 1 Frame → 注入重演命令到相机系统 → 相机移动 → 触发错乱
        │
错乱帧定位：对比本帧 vs 前一帧命令序列（Dispatch/Copy/ExecuteIndirect 结构）
  ——对齐 BugFix_L2c §6.1 "命令录制：两帧命令序列结构一致" 的对比模式
```

| 组件 | 职责 |
|:--|:--|
| `CameraCommandRecorder`（Editor 侧） | 每帧记录相机输入命令（移动/旋转增量）到环形缓冲——记录"如何移动"而非"移动到哪"（确定性重演） |
| 步进回放模式 | 暂停后步进：优先取实时输入；无输入则从命令缓冲按帧重演——**相机继续移动，错乱可触发** |
| 命令序列对比 | 错乱帧暂停时，转储本帧/上一帧命令序列（Dispatch/Copy/ExecuteIndirect 计数）——对照 BugFix §6.1 模式 |
| 双端同步 | CPU 端命令序列（相机输入）与 GPU 端帧执行同步——步进时重演命令，观察该帧渲染 |

**命令序列与录制功能紧密联系（2026-08-11 用户补充）**：

- **录制功能产出命令序列**：`CameraCommandRecorder`（以及 SnapshotSystem L3 `OperationRecorder`）的本质
  是**录制**——把每帧输入/操作记录成有序命令序列（相机增量命令 / Operation 列表），命令序列是
  录制的**产物**；
- **命令序列是回放的唯一输入**：单帧步进的**重演**（按帧重演相机增量）与 SnapshotSystem 的
  **游戏进程回放**（按帧重演操作序列）都**消费录制的命令序列**——没有录制，就没有可回放的
  命令序列，无输入步进无从谈起；
- **录制 ↔ 命令序列 ↔ 回放 一体三态**：
  ```
  录制（Record）：每帧采集输入/操作 → 追加到命令序列（环形缓冲 / Operation 列表）
     ↓
  命令序列（Command Sequence）：有序存储——回放与对比的**共同载体**
     ↓
  回放（Replay）：按帧取命令重演 → 相机移动/操作重放 → 触发错乱 / 验证确定性
  ```
- **命令序列对比复用同一载体**：错乱帧定位的"本帧 vs 上一帧命令序列对比"（Dispatch/Copy/
  ExecuteIndirect）与回放读的是**同一条命令序列**——录制、回放、对比三功能共享序列数据；
- **对齐 SnapshotSystem L3**：录制功能（`OperationRecorder` 命令序列 → 双向同步/游戏进程回放，
  docs 已记载）与单帧步进的相机命令录制是**同一模式的两个实例**（操作级 vs 相机输入级）——
  未来统一到 SnapshotSystem 录制框架时，单帧步进命令序列可直接纳入。

**触发方式**：常规大型引擎在 viewport 有步进开关（暂停/步进一帧按钮）——ImGui 窗口已实现（§2.3）；
**无输入步进是核心补充**——没有它，暂停态步进无法触发相机移动，错乱不可复现。

## 三、使用流程（用户操作）

```
1. 运行编辑器，打开 City4（或闪烁复现场景）
2. 移动相机至闪烁高发区（同时 CameraCommandRecorder 记录命令）→ 按"暂停"（画面冻结）
3. 按"步进一帧"逐步推进：
   - 有实时输入 → 用实时输入（手动微调逼近）
   - 无输入 → 自动从命令缓冲重演下一帧相机命令（相机继续移动，触发错乱）
4. 步进到错乱帧 → 保持暂停 → 查看状态转储（帧号/可见实例/桶数）+ 命令序列对比
5. 对照 BugFix 疑点 A/B/C 定位根因（或转储数据供分析）
```

## 五、风险与注意

- **暂停时长**：长时间暂停 GPU 帧资源不回收（fence 不推进）——调试场景可接受，但注意勿长期挂起；
- **DWM/Vsync**：暂停时 Present 停止，画面冻结在最后交换链帧（正常预期）；
- **BackgroundExecutor**：暂停时继续驱动（规则 15），异步加载任务完成回调照常触发；
- **命令缓冲容量**：环形缓冲（1024 帧）——超限覆盖最旧命令（仅调试，可接受）；记录"增量"而非"绝对位姿"保证确定性重演。
