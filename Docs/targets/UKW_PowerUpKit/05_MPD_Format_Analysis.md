### 0.1 权威结构（来自 mpd.cs load/save，与真实文件实测一致）

```
[头部]
  "MPD"           3B  ASCII 魔数
  WorldParts      int32 LE  固定 20000（0x00004E20；旧逆向把 0x20 0x4E 误读为版本标志）
  PiecesCount     int16 LE  固定 200（0xC8 00）

[Pieces 表] PiecesCount 条，每条：
  256B  visualMesh 名（Shift-JIS，\0 截断，定长槽）
  256B  collisionMesh 名（Shift-JIS，\0 截断，定长槽）
  3B    填充（FF FF 00）
  int32 scriptText 长度 N
  N B   scriptText（Shift-JIS；条级脚本，如空则 N=0）
  → 200 条 × 521B 定长起点 + 变长脚本；City 实测 43 个非空 visual

[WorldGrid 区]
  int16 x  格数（固定 100）
  int16 y  格数（固定 100）
  float unk 格尺寸（固定 30.0f = 0x0000F041；旧逆向的"结束标记"）
  然后 x×y 个格子（City 100×100），每格：
    int32 对象数 count
    count 个对象，每个：
      16 × float 矩阵（列主序！m00,m10,m20,m30 | m01,m11,m21,m31 | m02,m12,m22,m32 | m03,m13,m23,m33）
      int16 pieceID（索引 Pieces 表，0-based；198=Sky.x、199=Hit.x）
      int32 脚本长度 R
      R B   脚本（Shift-JIS，对象级渲染参数：@CullFar/@ShadowFlag/@AlphaTestFlag/#WaterY 等）
```

**要点**：
- **对象矩阵 = 完整世界变换**，平移列（m03,m13,m23 = 数组下标 12,13,14）即世界坐标 X/Y/Z（实测 City mapChip06 在 (1080, -2, 1170)，格步长 30 与 unk 吻合；旧逆向"矩阵≈单位阵"是解析错位导致的误判）
- **格子只是桶**：格子坐标 = 世界坐标 / 30 归桶（编辑器 addWorldObject: `x=Floor(pos.x/unk), y=Floor(pos.z/unk), WorldGrid[y,x]`），对象真身在矩阵里
- **`00 00 80 3F`(1.0f) 是矩阵对角线元素**（m00/m11/m22/m33，20B 间隔），不是段分隔符
- **MPD 存在明文与 XOR 加密两种变体**（2026-08-03 实测）：City/City2/City3/City_tac/In/In2/moon 头部明文 `"MPD"`；**City4/City5/skyland 头部为密文**，需 XOR 0x0B7E7759 解密后才是 `"MPD"` 开头（ParseFile 已实现"先明文 → XOR 兜底"自动处理）。`.x`/`.spt` 明文（实测 Road.x 头 `xof 0303bin` 明文）；`.dds`/`.png`/`.hod`/`.ani` 走 XOR 0x0B7E7759
- 编辑器的 CypherTranscoder（0x0B7E7759）对 .x/.png 的 XOR 是冗余防御，游戏侧 .x 明文

### 0.2 社区编辑器源码关键信息（C# 语义 → 引擎实现映射）

| 编辑器源码（mpd.cs） | 引擎侧含义 |
|:---|:---|
| `mpd_Piece{visualMesh, collisionMesh, scriptText}` | 地图 piece = 网格名对 + 条级脚本 |
| `mpd_Object{Matrix4x4 transform, short pieceID, int scriptIndex}` | 对象实例 = 世界矩阵 + piece 引用 |
| `Matrix4x4` 列主序存储，`GetColumn(3)` 取平移 | 世界坐标 = m03,m13,m23 |
| `addWorldObject` 按 pos/30 归桶 | 格子仅用于加载/剔除分块 |
| `scripts` 全局表去重 + scriptIndex | 对象脚本可去重（City 7623 对象仅 27 种脚本） |
| piece 198=Sky.x（scale 3000）、199=Hit.x | 与旧逆向"Sky.x/Hit.x 固定排除"一致 |
| Save 用 `Matrix4x4.TRS(pos,rot,scale)` 写矩阵 | 矩阵支持任意旋转/缩放（City 部分对象非单位阵） |

In: Sky=0 Hit=0     In2: Sky=0 Hit=0     moon: Sky=0 Hit=0    skyland: Sky=0 Hit=0

```
SPT 指令 LoadHitXFile(Hit.x) / LoadSkyXFile(Sky.x,...)
  → 引擎加载 Hit/Sky 网格 → 固定位置 (1500, 0, 1500)
  （社区编辑器源码 loadmpd 硬编码：HitArea/SkyMap localPosition = (1500,0,1500)；
    Sky scale=3000，Hit 无缩放）
```

**资产化含义**：
- MPD → scene.json 时普通对象照常导出；**Hit/Sky 从 SPT 层注入**（读 `LoadHitXFile`/`LoadSkyXFile` 指令 + 固定位置 (1500,1500)），不依赖 MPD 对象表
- Hit 网格 = 战斗边界（作战范围），可作为引擎"战斗区域"组件（碰撞边界/相机限制）
- **Hit 尺寸因图而异**：City_tac 的 Hit.x 为 724×804（非统一 200×200），其余图多为 200×200——每个地图的 Hit.x 文件内容独立

## 一、已知通用结构

### 1.1 文件头部（8 字节，所有地图一致）

| 偏移 | 大小 | 值 | 说明 |
|:----|:-----|:---|:------|
| 0x00 | 4B | `4D 50 44 20` (`"MPD "`) | 魔数 |
| 0x04 | 1B | `4E` (`'N'`) | 版本标志（所有地图相同） |
| 0x05 | 2B | `00 00` | 填充 |
| 0x07 | 2B | `C8 00` = **200** | 固定值（所有地图一致，非 tile 数量） |

### 1.2 名字表（FFFF0001 + 4B 定位，已确认 ✅）

名字表条目通过 `FFFF0001` 标记 + 4 字节偏移定位：

```
FFFF0001 [4B gap] [num] 01 00 00 00 [filename.x\0]
```

- 第一个名字在头部之后（偏移 9），直接搜索 `.x\0`
- 后续名字：找 `FFFF0001`，跳过 4 字节，再找 `[num] 01 00 00 00 [filename]`
- mesh 和 hit 间距自动检测（F5 或 F9，因文件而异）
- 不参与 tile 索引的特殊条目：`Sky.x`、`Hit.x`（固定排除）
- 可通过 `FilterByExistingFiles` 对比实际资产目录过滤

### 1.3 文本配置段（FFFF00XX + 3B 定位，已确认 ✅）

通过 `FFFF00XX + 3B` 模式定位（排除 `FFFF0001`），跳过前导 `00`，收集文本直到结束标记：

```
FFFF00 XX [3B gap] [text content] ... [end marker]
```

**结束标记**：`64 00 64 00 00 00 F0 41`（uint16=100, uint16=100, float=30.0）

**字段分隔**：`00` 作为字段分隔符，每个 `00` 分隔的段独立成条目
**空白忽略**：`0D 0A 20`（CRLF、空格）跳过

提取的指令：
```
LightColor(r,g,b);
FogColor(r,g,b);
LightDir(x,y,z);
BgmFileName(idx,name);
PopInfo(idx, ...);
AreaHitXFile;
SkyXFile;
LoadWaterXFile;
```

### 1.4 00 00 80 3F 文本标记（渲染参数，已确认 ✅）

`00 00 80 3F` 是**位置标记**，后面间隔 6 字节开始有渲染配置明文：

```
00 00 80 3F [6B gap] [render config text]
```

- 跳过前导 `00`
- 收集直到连续 3 个 `00` 或 `00 00 80 3F`
- 跳过 `0D 0A` 换行
- 检测 `@` 标记（用于统计，不省略）
- 统计含 `@` 和不含 `@` 的条目数

典型内容：
```
@ShadowFlag=1;
@CullFar=80;    'Far
@CullMode=1;    '球カリング
@AlphaTestFlag=1;   'alphaTest
@ShadowDrawFlag=0;  'ShadowDraw
WaterY=-0.5;
```

### 1.5 二进制 tile 实例段（⚠️ 部分解析）

条目以 `[num] 00 01` 开头，包含二进制数据（矩阵等）和坐标。结构因地图而异，**尚无通用解析方案**。

- **Moon**：矩阵≈单位阵，74 字节/条，结尾 `00 00 80 3F`

## 三、文本标记（`00 00 80 3F` 后的明文，已确认 ✅）

### 6.1 发现

`00 00 80 3F`（float 1.0）在 MPD 二进制中大量出现。它位于每条 tile 实例数据之后，作为**文本标记段的前导标记**。格式：

```
00 00 80 3F [头部] 明文 (Shift-JIS) 00 00 ...
```

其中头部通常为 `1F 00 88 00 00 00` 等固定字节，然后跟上可读的明文配置。

### 6.2 Moon 示例

解码后的文本（Shift-JIS → UTF-8）：

```
@ShadowFlag=1;
@CullFar=80;    'Far
@CullMode=1;    '球カリング
```

含义：
- `@ShadowFlag=1` — 开启阴影投影
- `@CullFar=80` — 可见距离 80 单位
- `@CullMode=1` — 球体裁剪模式
- `'球カリング` — 注释："球体剔除"

### 6.3 City 示例

City 的文本标记格式类似但更丰富，包含更多渲染参数：

```
@CullFar=50;    'Far
@AlphaTestFlag=1;   'alphaTest
@ShadowFlag=2;      'shadow
@ShadowDrawFlag=0;  'ShadowDraw
'@CullMode=1;       '攻撃設定
```

### 6.4 统计

| 地图 | 文件大小 | `00 00 80 3F` 出现次数 | 含文本数 |
|:-----|:--------|:----------------------|:---------|
| Moon | 174KB | 761 | 428 |
| City | 1.4MB | 20647 | 18533+ |

> 注意：并非所有 `00 00 80 3F` 后面都有可读文本，有些是纯二进制数据中碰巧出现的模式。

### 6.5 用途

这些文本标记是**每条 tile 实例的渲染参数配置**，对应每帧渲染时的状态设置。可用于：
- 验证 tile 实例的数量和位置
- 获取每个 tile 的渲染属性（阴影、裁剪距离等）
- 辅助理解 tile 实例段的边界

### 6.6 00 00 80 3F 作为位置标记

`00 00 80 3F` 不是块分隔符，而是一种**位置标记**，位于每个 `[num] 00 01` 条目内部，用于标记矩阵对角线元素和渲染文本段。

## 七、结构化标记模式（2026-07-10 发现）

### 7.1 名字表：FFFF0001 + 4B 定位

名字表条目通过 `FFFF0001` 标记 + 4 字节偏移定位：

```
FFFF0001 [4B gap] [num] 01 00 00 00 [filename.x\0]
```

- `FFFF0001` 标记在所有地图中极其稳定可靠 ✅
- 跳过 4 字节后，即是 `[num] 01 00 00 00 [filename]`
- 第一个名字也可通过此模式找到

#### mesh-hit 间距自动检测

同一模型的两个变体（mesh 和 hit，如 `map00.x` 和 `map00hit.x`）之间的距离是固定的，但**因文件而异**，运行时自动检测。

### 7.2 FFFF00XX 标记体系

`FFFF00XX` 是 MPD 文件中的**通用段标记**，其中 XX 表示段类型：

| 标记 | 间距 | 用途 |
|:-----|:------|:------|
| `FFFF0001` | **204** 字节固定 | 通用数据块（可能含零或文件名，不是 tile 实例） |
| `FFFF00XX` + 3B → 明文 | 间距 3 | 文本配置段（如 `AreaHitXFile;`） |
| `FFFF00XX` + 4B → 名字 | 间距 4 | 名字表条目 |

### 7.3 文本段定位

在 `FFFF00XX` 标记后间隔 **3 字节** 即可找到明文内容：

```
FFFF00 XX [3B gap] '明文内容...
```

### 7.4 第一组 FFFF0001

- 总是偏移头部一个固定值（0-208，大小 209）
- 内部以 204 字节步进
- 不保证包含名字参数，也可能全为 0

## 八、00 00 80 3F 标记间距（核心解析模式）

### 8.1 标记间距基础

`00 00 80 3F`（float 1.0）在每个 `[num] 00 01` 条目内部出现多次，标记间距固定：

| 间距 | 含义 |
|:-----|:------|
| **20B** | 4×4 矩阵对角线元素间距（5 floats × 4B） |
| **>20B** | 渲染文本段（20B 矩阵 + 渲染参数） |

### 8.2 各地图标记间距模式

| 地图 | 标记数 | 间距模式 | 渲染文本 |
|:-----|:-------|:---------|:---------|
| **In** | 4 | `20,20,20` | 无 |
| **Moon** | 4 | `20,20,20` | 极少（4% 条目） |
| **City2/City** | 8 | `20,20,20,30,20,20,20` | 84% 条目有 |
| **City5** | 6~8 | 重复 `20,20,20,211` | 100% 条目有 |
| **City3** | 4/8 | 混合 | 8% 条目有 |
| **City_tac** | 4 | `20,20,20` | 无 |

### 8.3 渲染文本定位

渲染文本始终位于 `00 00 80 3F` 标记后 **+6 字节**：

```
00 00 80 3F [6B gap] @ShadowFlag=1; @CullFar=80; ...
```

### 8.4 条目完整结构

```
[num] 00 01 [矩阵数据] 00 00 80 3F [+6B → 渲染文本] 00 00 80 3F [+6B → 渲染文本] ...
```

- 标记间距 = 20B：纯矩阵数据
- 标记间距 > 20B：矩阵 + 渲染文本段
- 标记位于每个 `[num] 00 01` 条目内部，渲染文本跟随条目，非离散

名字表条目通过 `FFFF0001` 标记 + 4 字节偏移定位：

```
FFFF0001 [4B gap] [num] 01 00 00 00 [filename.x\0]
```

- `FFFF0001` 标记在所有地图中极其稳定可靠 ✅
- 跳过 4 字节后，即是 `[num] 01 00 00 00 [filename]`
- 第一个名字也可通过此模式找到

#### mesh-hit 间距自动检测

同一模型的两个变体（mesh 和 hit，如 `map00.x` 和 `map00hit.x`）之间的距离是固定的，但**因文件而异**：

| 地图 | mesh-hit 间距 | 实测 |
|:-----|:-------------|:------|
| Moon | F5 (245) | ✅ |
| City | F5 (245) | ✅ |
| City5 | **F9 (249)** | ✅（与 City 不同！） |
| In | F9 (249) | ✅ |

> 关键：间距不是由地图类型决定，而是**每个文件独立**。City 和 City5 虽然是同类地图但间距不同（F5 vs F9）。

**运行时自动检测算法**：
1. 通过 `FFFF0001 + 4B` 收集所有名字
2. 找到第一个 mesh 名字（如 `map00.x`）
3. 找到它的 hit 版本（`map00hit.x`）
4. 测量两者间距 → 作为本文件的固定步长
5. 按此步长过滤所有名字，只保留对齐的条目

这样无论 F5 还是 F9，甚至其他值，都能自动适应。

### 7.2 FFFF00XX 标记体系

`FFFF00XX` 是 MPD 文件中的**通用段标记**，其中 XX 表示段类型：

| 标记 | 间距 | 用途 |
|:-----|:------|:------|
| `FFFF0001` | **204** 字节固定 | 通用数据块（可能含零或文件名，不是 tile 实例） |
| `FFFF0001` 内部 | 204B 步进 | 可能全零，不一定有名称参数 |
| `FFFF0030` | 不定 | BGM/配置文本前导 |
| `FFFF00XX` + 3B → 明文 | 间距 3 | 文本配置段（如 `AreaHitXFile;`） |
| `FFFF00XX` + 4B → 名字 | 间距 4 | 名字表条目 |

### 7.3 文本段定位

在 `FFFF00XX` 标记后间隔 **3 字节** 即可找到明文内容：

```
FFFF00 XX [3B gap] '明文内容...
```

示例：
```
FFFF00 30 [3B] 'BgmFileName(0,fuse.ogg);
```

文本内容一直持续到 `00 00 80 3F` 出现为止。

### 7.4 第一组 FFFF0001

- 总是偏移头部一个固定值（0-208，大小 209）
- 内部以 204 字节步进
- 不保证包含名字参数，也可能全为 0

## 八、PopInfo / 出生点结构

### 8.1 三标记单元结构

每个 PopInfo 出生点由三个标记分隔的固定结构组成：

```
标记1: 00 00 80 BF  (-1.0)
18B:   [3 floats 坐标 + 标记 ID + 填充]
标记2: 00 00 80 3F  (1.0)
8B:    [2 × uint16 参数 + 文本头 (0x27 = ')]  
文本:  '[N]TeaamNo \r\nPopInfo(N, ...);\r\n'  (变长)
9B:    00 2E BD 3B B3 00 00 00 00  ← 固定 9 字节后缀（恒存在，全 0 也不例外）
标记3: 00 00 80 3F  (1.0)
```

### 8.2 字段明细

| 段 | 长度 | 内容 |
|:---|:-----|:------|
| 标记1 | 4B | `00 00 80 BF` = -1.0 |
| 坐标+ID | 18B | 6B 前导 + 12B(3 floats: X, Y, Z) |
| 标记2 | 4B | `00 00 80 3F` = 1.0 |
| 参数头 | 8B | 2×uint16 + 2B 文本头 |
| 文本 | 变长 | `'[N]TeaamNo \r\nPopInfo(N, ...);\r\n` |
| 后缀 | **9B** | `00 2E BD 3B B3 00 00 00 00`（固定，全零也存在） |
| 标记3 | 4B | `00 00 80 3F` = 1.0 |

### 8.3 解析规则

- 找到 `00 00 80 BF`（标记1）→ 后面 18 字节含坐标
- 找到 `00 00 80 3F`（标记2）→ 后面 8 字节含参数
- 提取文本 `PopInfo(...)` 直到 9 字节后缀
- 遇到 `00 00 80 3F`（标记3）→ 单元结束
- 当标记间间隔不符合 18B/8B/9B 模式时，PopInfo 段结束

## 十、00 00 80 3F/00 00 80 XF 标记间距模式

### 10.1 通用规律

`00 00 80 3F` 和 `00 00 80 XF`（末字节以 0F 结尾，如 BF、3F 等）是 MPD 中广泛使用的**分隔符/位置标记**。`00 00 80 BF` 常作为条目起始标记。

### 10.2 模式一：四标记 + 渲染参数（City5）

```
标记1: 00 00 80 3F
[10B] ← 00 00 00 00 00 00 00 00 00 00（全零）
标记2: 00 00 80 3F
[10B] ← 00 00 00 00 00 00 00 00 00 00（全零）
标记3: 00 00 80 3F
[18B] ← 坐标 X/Y/Z
标记4: 00 00 80 3F
[6B]  → 渲染参数明文（@CullFar=, @ShadowFlag= 等）
[Shift-JIS 注释 + 0D 0A]
[3B]  → 下一个标记
```

### 10.3 模式二：XF 起始 + 四标记

```
标记1: 00 00 80 XF  ← XF 末字节以 0F 结尾（BF、3F 等）
[8B]
标记2: 00 00 80 3F
[8B]
标记3: 00 00 80 3F
[18B] ← 坐标 X/Y/Z
标记4: 00 00 80 3F
[6B]  → 渲染参数明文（或无，若无参数则到 6 仍无有效数据）

[2E BD 3B B3 标记区]
0D 0A 00 2E BD 3B B3 00 00 00 00  ← 11B (0xB) 固定块
这个 11B 块出现在明文和 00 00 80 XF 之间，作为 XF 之间的分隔符
```

### 10.4 标记间距汇总

| 位置 | 间距 | 内容 |
|:-----|:-----|:------|
| 标记1→标记2 | **8B** | 数据 |
| 标记2→标记3 | **8B** | 数据 |
| 标记3→标记4 | **18B** | 坐标 X/Y/Z |
| 标记4→文本 | **6B** | 渲染参数明文 |
| 明文→下一个标记 | **3B** | 间距 |
| XF 之间 | 11B (0xB) | `0D 0A 00 2E BD 3B B3 00 00 00 00` |

### 10.5 关键标记

| 标记 | 值 | 含义 |
|:-----|:----|:------|
| `00 00 80 BF` | -1.0 float | 条目起始标记 |
| `00 00 80 3F` | 1.0 float | 条目内部标记 |
| `2E BD 3B B3` | uint32=3007036718 | XF 之间的分隔符，出现在 11B 块中 |

## 十二、条目锚点模式与通用结构（2026-07-11 发现）

### 12.1 条目锚点：`XX 00 00 00 00 00 80 3F`

通过对 Moon、In、City5、City 等地图的系统比对，发现所有地图的 tile 条目都以一个固定模式开头：

```
XX 00 00 00 00 00 80 3F
```

其中 `XX` 是**地图特有的标识字节**，`00 00 00 00 00` 是固定填充，`00 00 80 3F` 是第一个标记。

**各地图的 XX 值：**

| 地图 | XX | 说明 |
|:-----|:---|:------|
| Moon | `0x01` | 纯 3F 模式，84 条 |
| In | `0x02` | 混合 BF 模式 |
| City5 (3F) | `0x10` | 3F 条目，441 条；另有 807 BF 条目 |
| City_tac | `0x01` | 大量 BF 条目 |
| City / City2 | `0x02` | 大量 BF 条目 |
| City3 | `0x01` | 小地图 |
| City4 | `0x22` | 独特 XX 值 |
| In2 | `0x01` | 混合 BF 模式 |
| Skyland | `0x0e` | 结构特殊，待分析 |

> **注意：** `XX=0x00` 是假阳性（`00 00 00 00 00 00 80 3F` 只是 3F 标记本身前面恰好有 4 个零），解析时排除。

### 12.2 Type A：3F 起始条目（4 标记，16-16-16 间隔）

这是 Moon、City5 3F 条目、In 3F 条目等使用的标准格式：

```
偏移 0:  [XX]              ← 地图标识字节
偏移 1:  [00 00 00]        ← 固定填充
偏移 4:  [00 00 80 3F]     ← 标记1 (m1)
偏移 8:  [16B data]        ← 间隔1 (gap1)，通常为全零
偏移 24: [00 00 80 3F]     ← 标记2 (m2)
偏移 28: [16B data]        ← 间隔2 (gap2)，通常为全零
偏移 44: [00 00 80 3F]     ← 标记3 (m3)
偏移 48: [16B: 4B零 + X:4B + 4B零 + Z:4B]  ← 间隔3 (gap3)，坐标区
偏移 64: [00 00 80 3F]     ← 标记4 (m4)
偏移 68: [index:uint16 LE] ← tile 索引（0-based，对应名字表）
偏移 70: [param:uint16 LE] ← 参数
偏移 72+: [text...]        ← 渲染参数明文（可选）
```

**坐标提取：** gap3 偏移 +4 → X(float)，+8 → Y(float，=0)，+12 → Z(float)

**示例（Moon）：**
```
01 00 00 00 00 00 80 3F  ← 锚点
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  ← gap1 全零
00 00 80 3F              ← m2
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  ← gap2 全零
00 00 80 3F              ← m3
00 00 00 00 00 C0 A8 44 00 00 00 00 00 C0 A8 44  ← gap3: X=1350.0, Z=1350.0
00 00 80 3F              ← m4
[09 00]                  ← index=9
[01 00]                  ← param=1
```

### 12.3 Type B：BF 起始条目（4 标记，8-8-24 间隔）

City5、City、City_tac、In2 等地图中大量存在，以 `00 00 80 BF` 代替 `00 00 80 3F` 作为起始标记：

```
偏移 0:  [00 00 80 BF]     ← 标记1 (BF)
偏移 4:  [8B data]         ← 间隔1 (gap1)，通常为全零
偏移 12: [00 00 80 3F]     ← 标记2 (m2)
偏移 16: [8B data]         ← 间隔2 (gap2)，通常为全零
偏移 24: [00 00 80 3F]     ← 标记3 (m3)
偏移 28: [24B: 4B零 + 4B分隔符 + 4B零 + X:4B + 4B零 + Z:4B]  ← 间隔3 (gap3=0x18)，坐标区
偏移 52: [00 00 80 3F]     ← 标记4 (m4)
偏移 56: [index:uint16 LE] ← tile 索引
偏移 58: [param:uint16 LE] ← 参数
偏移 60+: [text...]        ← 渲染参数明文
```

**坐标提取：** gap3 偏移 +12 → X(float)，+20 → Z(float)

**分隔符：** `2E BD 3B B3` 出现在 gap3 偏移 +4 处

### 12.4 各地图条目类型统计

| 地图 | Type A (XX锚点) | Type B (BF) | 合计 |
|:-----|:---------------|:------------|:----|
| Moon | 84 (0x01) | 0 | 84 |
| In | 255 (0x02) | 274 | ~529 |
| City5 | 441 (0x10) | 807 | 1248 |
| City_tac | 686 (0x01) | 4800 | ~5486 |
| City | 267 (0x02) | 3903 | ~4170 |
| City2 | 267 (0x02) | 3903 | ~4170 |
| City3 | 82 (0x01) | — | ~82 |
| City4 | 196 (0x22) | 1 | ~197 |
| In2 | 28 (0x01) | 215 | ~243 |
| Skyland | 48 (0x0e) | 0 | 特殊 |

### 12.5 解析算法

```
1. 扫描数据，统计所有 XX 00 00 00 00 00 80 3F 模式（XX ≠ 0）
2. 取出现次数最多的 XX 作为锚点值
3. 遍历所有锚点匹配：
   a. 验证 4 个连续 3F 标记，间隔 16-16-16
   b. 从 gap3 偏移 +4/+8/+12 提取坐标 X/Y/Z
   c. 从 m4+4 提取 index，m4+6 提取 param
4. 扫描所有 00 00 80 BF 标记：
   a. 验证 3 个后续 3F 标记，间隔 8-8-24
   b. 从 gap3 偏移 +12/+20 提取坐标 X/Z
   c. 从 m4+4 提取 index，m4+6 提取 param
5. 合并所有条目，按 index 去重
```

### 12.6 社区版问题

社区版（`_test_city5_pattern.ps1`）使用 `$gap1 = 10`（十进制 10）作为 3F 标记间隔，但实际间隔为 **16 字节（0x10）**。且 BF 情况的坐标偏移计算错误（脚本从 m3+4+6 取坐标，实际应从 gap3 偏移 +12 取）。
